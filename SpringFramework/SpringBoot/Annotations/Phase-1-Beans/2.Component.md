

# @Component in Spring Boot

---

# 1. What is `@Component`?

`@Component` tells Spring:

> "Create and manage an object of this class automatically."

This object becomes a **Spring Bean**.

---

# 2. What is a Bean?

A Bean is simply:

> An object managed by Spring.

Without Spring:

```java
EmailService service = new EmailService();
```

You create objects manually.

With Spring:

```java
@Component
public class EmailService {
}
```

Spring creates the object for you.

---

# 3. Why Do We Need `@Component`?

Imagine a large application:

- 500 classes
- services depending on other services
- repositories depending on databases
- controllers depending on services

Creating objects manually becomes painful.

Spring solves this using:

- Dependency Injection
- Inversion of Control (IoC)

`@Component` is the starting point.

---

# 4. What Happens Internally?

When Spring Boot starts:

1. It scans packages
2. Finds classes annotated with `@Component`
3. Creates objects
4. Stores them inside the ApplicationContext
5. Injects them wherever needed

This process is called:

## Component Scanning

---

# 5. Basic Example

```java
@Component
public class EmailService {

    public void sendEmail() {
        System.out.println("Email Sent");
    }
}
```

Using it:

```java
@RestController
public class UserController {

    private final EmailService emailService;

    public UserController(EmailService emailService) {
        this.emailService = emailService;
    }

    @GetMapping("/send")
    public String send() {
        emailService.sendEmail();
        return "done";
    }
}
```

Spring automatically injects `EmailService`.

---

# 6. Where Does Spring Scan?

By default:

Spring scans:

- current package
- subpackages

Example:

```text
com.example.app
 ├── controller
 ├── service
 └── repository
```

If your main class is:

```java
package com.example.app;
```

everything below gets scanned.

---

# 7. Common Beginner Mistake

## Problem

```text
Main Class:
com.example.app

Service:
com.other.service
```

Spring WON'T scan it.

Result:

```text
NoSuchBeanDefinitionException
```

---

# 8. Fixing Scan Problems

Use:

```java
@SpringBootApplication(scanBasePackages = {
    "com.example.app",
    "com.other.service"
})
```

OR place the main class at the root package.

Best practice:

```text
com.company.project
```

and everything inside it.

# 9. `@Component` and Dependency Injection

Example:

```java
@Component
public class PaymentService {
}
```

```java
@Component
public class OrderService {

    private final PaymentService paymentService;

    public OrderService(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}
```

Spring sees:

- OrderService needs PaymentService
- finds PaymentService bean
- injects it automatically

This is Dependency Injection.

---

# 10. Constructor Injection vs Field Injection

## Bad Practice

```java
@Autowired
private PaymentService paymentService;
```

Why bad?

- hard to test
- hidden dependency
- reflection usage
- immutability impossible

---

## Best Practice

```java
private final PaymentService paymentService;

public OrderService(PaymentService paymentService) {
    this.paymentService = paymentService;
}
```

Advantages:

- immutable
- testable
- cleaner
- recommended officially

---

# 11. Is `@Component` Mandatory?

No.

You can create beans using:

```java
@Bean
```

inside:

```java
@Configuration
```

Example:

```java
@Configuration
public class AppConfig {

    @Bean
    public EmailService emailService() {
        return new EmailService();
    }
}
```

---

# 12. When Should You Use `@Component`?

Use when:

- YOU own the class
- simple object creation
- automatic scanning desired

Examples:

- utility classes
- helper classes
- validators
- custom services
- mappers

---

# 13. When NOT to Use `@Component`

Avoid when:

- object creation is complex
- third-party library class
- conditional bean creation needed
- custom initialization logic needed

Then use:

```java
@Bean
```

instead.

---

# 14. Difference Between `@Component` and `@Bean`

| Feature | @Component | @Bean |
|---|---|---|
| Object creation | Automatic | Manual |
| Who owns class | Your class | Third-party possible |
| Flexibility | Less | More |
| Easy to use | Yes | Medium |
| Conditional logic | Hard | Easier |

---

# 15. Specialized Versions of `@Component`

These are ALL internally `@Component`.

| Annotation | Purpose |
|---|---|
| `@Service` | business logic |
| `@Repository` | database layer |
| `@Controller` | MVC controller |
| `@RestController` | REST API controller |

Internally:

```java
@Service
== @Component
```

BUT semantic meaning matters.

# 17. Bean Naming

Default bean name:

```java
@Component
public class EmailService
```

Bean name becomes:

```text
emailService
```

(lower camel case)

Custom name:

```java
@Component("customEmailService")
```

# 18. Bean Scope

Default scope:

## Singleton

Only ONE object exists.

Example:

```java
@Component
public class UserService {
}
```

One instance shared everywhere.

---

# 19. Other Scopes

```java
@Scope("prototype")
```

creates new object every time.

Other scopes:

- request
- session
- application

Mostly used in web applications.

---

# 20. Common Production Problems

## A. Circular Dependency

Example:

```java
A -> B
B -> A
```

Spring may fail startup.

Error:

```text
BeanCurrentlyInCreationException
```

Usually indicates bad design.

---

## B. Too Many Components

Excessive scanning slows startup.

---

## C. Hidden Dependencies

Field injection causes confusion.

---

# 21. Thread Safety Issue

Because singleton beans are shared:

BAD:

```java
@Component
public class CounterService {

    private int count = 0;

    public void increment() {
        count++;
    }
}
```

Multiple requests may corrupt data.

Singleton beans should ideally be stateless.

# 23. Internal Technical Details

`@Component` is itself an annotation:

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
```

Spring uses reflection to detect it during startup.

---

# 24. Advantages of `@Component`

- automatic object creation
- less boilerplate
- easier dependency management
- integrates with Spring ecosystem
- clean architecture

---

# 25. Drawbacks of `@Component`

- magic behavior for beginners
- hidden object creation
- startup scanning overhead
- difficult debugging sometimes
- accidental bean creation possible

---

# 26. Best Practices

## DO

- use constructor injection
- keep beans stateless
- organize packages properly
- use semantic annotations (`@Service`)

---

## DON'T

- use field injection
- store mutable shared state
- create giant god classes
- scan unnecessary packages

---

Think of `@Component` as:

```text
"Spring, please create and manage this object for me."
```

# 28. Simple Real-Life Analogy

Without Spring:

You cook food yourself every time.

With Spring:

You ask a restaurant kitchen.

`@Component` means:

> "This dish should always be available in the kitchen."

---

# 29. Summary

`@Component` is the foundation of Spring Dependency Injection.

It tells Spring to:

- detect the class
- create an object
- manage lifecycle
- inject dependencies

Most higher-level Spring concepts build on top of this.

Understanding `@Component` properly makes:
- `@Service`
- `@Repository`
- `@Autowired`
- `@Bean`
- auto configuration

much easier later.
