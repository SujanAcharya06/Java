
# @Service in Spring Boot

---

# 1. What is `@Service`?

`@Service` marks a class as:

# Business Logic Layer

Example:

```java
@Service
public class PaymentService {
}
```

It tells Spring:

> "This class contains business logic and should become a Spring Bean."

---

# 2. Is `@Service` Different From `@Component`?

Internally:

# NO (mostly)

`@Service` is a specialized version of:

```java
@Component
```

Internally simplified:

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Component
public @interface Service {
}
```

Meaning:

```text
@Service
        IS-A
@Component
```

Spring still creates/manages the object exactly the same way.

---

# 3. Then Why Does `@Service` Exist?

Because software architecture matters.

Spring wants code to be organized into layers.

---

# 4. Typical Spring Architecture

```text
Client
  ↓
Controller Layer
  ↓
Service Layer
  ↓
Repository Layer
  ↓
Database
```

Each layer has responsibility.

---

# 5. Responsibility of `@Service`

Service layer usually contains:

- business rules
- validations
- workflows
- calculations
- transaction boundaries
- orchestration
- calling repositories
- calling external APIs

---

# 6. Example Without Service Layer (BAD)

```java
@RestController
public class UserController {

    @PostMapping("/users")
    public void createUser() {

        // validation
        // business logic
        // database logic
        // email sending
        // payment logic

    }
}
```

Problems:

- giant controllers
- difficult testing
- poor separation
- messy architecture

---

# 7. Proper Layered Architecture

## Controller

```java
@RestController
public class UserController {

    private final UserService userService;

    public UserController(
        UserService userService
    ) {
        this.userService = userService;
    }

    @PostMapping("/users")
    public void createUser(
        @RequestBody UserRequest request
    ) {
        userService.createUser(request);
    }
}
```

---

## Service

```java
@Service
public class UserService {

    private final UserRepository repository;

    public UserService(
        UserRepository repository
    ) {
        this.repository = repository;
    }

    public void createUser(UserRequest request) {

        validate(request);

        User user = new User();
        user.setName(request.getName());

        repository.save(user);

        sendWelcomeEmail(user);
    }
}
```

---

# 8. Why Is This Better?

Advantages:

- cleaner architecture
- reusable business logic
- easier testing
- separation of concerns
- smaller controllers
- maintainable code

# 10. `@Service` Is Usually Singleton

Default scope:

```java
@Service
public class PaymentService {
}
```

Spring creates ONE object.

Shared everywhere.

---

# 11. Why Singleton Services Are Safe

Because services SHOULD be:

# Stateless

GOOD:

```java
@Service
public class PaymentService {

    public void process() {
    }
}
```

No mutable shared fields.

---

# 12. Dangerous Service Design

BAD:

```java
@Service
public class PaymentService {

    private User currentUser;
}
```

Problem:

All requests share same singleton object.

Can cause:

- race conditions
- data corruption
- thread safety issues

---

# 13. Thread Safety in Services

Spring Boot web applications are multithreaded.

Example:

```text
User A request
User B request
User C request
```

All may use SAME service object simultaneously.

Therefore:

# Singleton services must ideally be stateless.

---

# 14. What Happens Internally?

At startup:

```text

    ↓
Find @Service classes
    ↓
Create objects
    ↓
Store inside ApplicationContext
```

Exactly same as `@Component`.

# 16. Custom Bean Name

```java
@Service("stripePaymentService")
```

---

# 17. Multiple Service Implementations

Example:

```java
public interface PaymentService {
    void pay();
}
```

---

## Stripe

```java
@Service
public class StripePaymentService
    implements PaymentService {
}
```

---

## PayPal

```java
@Service
public class PaypalPaymentService
    implements PaymentService {
}
```

Problem:

```text
NoUniqueBeanDefinitionException
```

because Spring finds 2 beans.

---

# 18. Fix Using `@Primary`

```java
@Primary
@Service
public class StripePaymentService
    implements PaymentService {
}
```

Now Spring chooses Stripe by default.

---

# 19. Fix Using `@Qualifier`

```java
public OrderService(
    @Qualifier("paypalPaymentService")
    PaymentService paymentService
) {
}
```

Explicit bean selection.

# 22. Service-to-Service Communication

Services can depend on other services.

Example:

```java
@Service
public class OrderService {

    private final PaymentService paymentService;
    private final EmailService emailService;

    public OrderService(
        PaymentService paymentService,
        EmailService emailService
    ) {
        this.paymentService = paymentService;
        this.emailService = emailService;
    }
}
```

Spring resolves dependency graph automatically.

---

# 23. Circular Dependency Problem

BAD:

```text
OrderService -> PaymentService
PaymentService -> OrderService
```

May cause:

```text
BeanCurrentlyInCreationException
```

Usually indicates bad design.

---

# 24. `@Transactional` Is Commonly Used With Services

Very important.

Most transaction boundaries belong in service layer.

Example:

```java
@Service
@Transactional
public class PaymentService {
}
```

Because service layer represents business workflow.

- transactions

- auditing

```java

@Service

}
```

# 33. Drawbacks

Not direct drawbacks of annotation itself,
but poor usage causes:

- god services
- giant business classes
- tightly coupled services
- circular dependencies

---

# 34. What Is a God Service?

BAD:

```java
UserService
```

containing:

- auth
- payment
- email
- invoices
- analytics
- notifications

Huge class.

Hard to maintain.

---

# 35. Best Practices

## DO

- keep services focused
- keep services stateless
- use constructor injection
- place transactions in services
- separate business rules properly

---

## DON'T

- put database queries directly in controller
- store request-specific state
- inject ApplicationContext unnecessarily
- create giant service classes

---

Spring uses stereotype annotations during scanning.

Stereotypes:

```text

@Service

@Controller
```
